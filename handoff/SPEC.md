# 고교선택 적성검사 v2 — 마스터 스펙 (SPEC)

> ⚠️ **핸드오프 원칙**: 이 문서·`QUESTIONS.json`·`WEIGHTS.json`·`index.html`(참조 구현) 4개가 모두 일치해야 한다. 충돌이 있으면 **`index.html`이 정답** (실제로 검증된 동작이므로). 새 구현이 이 4개와 한 글자라도 다르면 회귀(regression)다.

## 0. 프로젝트 정체성

한국 중·고교 학부모(특히 중2 2학기~중3 1학기 결정기)를 위한 **고교 선택 적성 검사**. 7개 고교 유형(일반고/자공고2.0/자사고/외고/국제고/과학고/영재학교) 중 학생의 성향과 가장 잘 맞는 후보군 1~3순위를 산출한다.

핵심 명제: **"내 아이의 성향 ↔ 학교 시스템의 적합도"**

배경 변수 3가지:
- 2025학년도 고1부터 내신 5등급제 (이전: 9등급제)
- 고교학점제 전면 시행 — 학생이 선택과목을 직접 설계, 절대평가/상대평가 공존
- "명문고 신화"의 붕괴 — 같은 유형 안에서도 학교별 편차가 유형 간 편차보다 크다

## 2. 6개 평가 축 (총 39문항)

### 축 A · 학업 성향·학습 체력 (Academic Fit) — 8문항

> "고교 3년을 버틸 수 있는 학습 체력과 회복탄력성"
> 하위지표: A1 절대 학습량 수용도, A2 경쟁 스트레스 내성, A3 자기주도성, A4 심화·선행 소화 능력

### 축 B · 진로 명확도·계열 적합성 (Career Direction) — 4문항 + 계열 선택(B2)

> "진로가 7할 이상 확정된 아이"와 "탐색 중인 아이"를 완전히 다르게 판단한다.
> B2는 별도 multi-select 문항: 8개 계열 중 복수 선택 + "잘 모르겠다" 옵션.

### 축 C · 입시 전략 (Admission Strategy Fit) — 5문항

> 수시(내신·학교생활 활동)·수능(정시)·논술 중 어느 트랙 체질인가.

### 축 D · 환경·생활·비용 (Environment & Cost) — 5문항

> **과소평가되지만 중도이탈 사유 1순위.** 통학시간(편도 60분 임계), 기숙 적응, 연 1천~2천만 원대 학비 부담 가능 여부.
> 이 축은 **보호자 응답 권장**.

### 축 E · 심리·사회성·분위기 (Psychosocial Fit) — 6문항

> 경쟁·서열 노출 내성, 또래 동질성 vs 다양성 선호, 비교 자존감 민감도.

### 축 F · 멘탈 유형 (Mental Type) — 10문항 ★신규

> 가이드e북의 청소년 인성검사 구조를 차용한 **성격 5요인(Big Five)**.
> 각 요인 2문항씩: N(정서적 안정성), E(외향성), C(성실성), O(개방성), A(우호성).

> ⚠️ 모든 39문항의 정확한 텍스트·id·역문항(reverse) 플래그는 `QUESTIONS.json`을 참조. **한 글자도 바꾸면 안 됨.**

## 3. 응답 척도

5점 리커트 척도. 라벨은 한국어 그대로:
1. 전혀 그렇지 않다
2. 그렇지 않은 편
3. 보통이다
4. 그런 편이다
5. 매우 그렇다

**역문항(reverse)** 처리: `value = 6 - response`. 현재 역문항은 2개 (`E2-2`, `E3-1`).

## 5. 스코어링 알고리즘 (반드시 이 순서)

### 5.1 축별 점수 계산

```
각 축 i에 대해:
  responses_i = 해당 축 문항들의 응답값 (역문항이면 6-x로 변환)
  axis_score_i = ((avg(responses_i) - 1) / 4) * 100   // 0~100
```

### 5.2 Big Five 5요인 점수 계산

F축 10문항 중 sub 코드(N/E/C/O/A)별로 그룹화. 각 요인별로 위와 동일한 정규화.

### 5.3 멘탈 유형 분류 (classifyMentalType) — 우선순위 순서대로 평가, **첫 번째 매치 반환**

1. **회복·보호형** (`protective`): `N < 50`
2. **강철 멘탈형** (`resilient`): `N >= 70 AND C >= 65`
3. **도전·탐험형** (`explorer`): `O >= 65 AND E >= 60`
4. **신중·정밀형** (`planner`): `C >= 65 AND E < 50`
5. **공감·협력형** (`connector`): `A >= 65 AND E >= 55`
6. **균형·탐색형** (`balanced`): 그 외 (기본값)

각 유형별 메타데이터(name·icon·tone·summary·strength·careful·fitTypes)는 **`WEIGHTS.json`의 `MENTAL_TYPES` 참조**.

> ⚠️ 회복·보호형 임계값 `N < 50`은 매우 중요한 안전장치. 절대 낮추지 말 것 (이전에 N=48인 사용자가 외고에서 적응 어려웠던 실제 케이스를 반영).

### 5.4 7개 고교 유형 적합도 점수 — 다음 4단계 누적

#### (a) 축 점수 × `AXIS_TYPE_WEIGHTS`

```
norm_score = (axis_score - 50) / 50   // -1.0 ~ +1.0
type_scores[hs] += norm_score * AXIS_TYPE_WEIGHTS[axis][hs] * 10
```

#### (b) 계열 보너스 (`TRACK_TYPE_BONUS`)

`careerSelections`가 비어있거나 `unsure`만 포함하면:
```
일반고 +4, 자공고2.0 +4, 자사고 -2, 외고 -1.5, 국제고 -1.5, 과학고 -2, 영재학교 -2
```

그 외(실제 계열 선택):
```
실제 계열들의 tracks를 합산해 정규화 (총합 = 1)
type_scores[hs] += weight * TRACK_TYPE_BONUS[track][hs] * 4
```

#### (c) 멘탈 보너스 (`mentalTypeBonus(big5)`)

N(정서적 안정성)이 가장 결정적. 4단계 임계값:

| N 점수 | 적용 보너스 |
|---|---|
| `N < 35` | 일반고+2.5, 자공고2.0+2.8, 자사고-4.0, 외고-3.5, 국제고-3.5, 과학고-3.5, 영재학교-4.5 |
| `N < 50` | 일반고+1.8, 자공고2.0+2.0, 자사고-2.8, 외고-2.3, 국제고-2.3, 과학고-2.3, 영재학교-3.0 |
| `N < 60` | 일반고+0.4, 자공고2.0+0.4, 자사고-0.5, 영재학교-0.7 |
| `N >= 75` | 자사고+1.0, 영재학교+1.0, 과학고+1.0, 외고+0.5, 국제고+0.5 |

E·C·O·A 각각의 임계값별 추가 보너스는 `WEIGHTS.json` 참조.

#### (d) 0~100 변환

```
final_scores[hs] = clamp(0, 100, round(50 + type_scores[hs] * 1.5))
```

### 5.5 ★ 안전장치 cap 후처리 — **반드시 (d) 다음에 적용**

> 두 cap은 단순 가중치만으로는 다른 축 점수가 매우 높을 때 부적합 학교가 다시 상위로 올라오는 위험을 막는 **최후의 안전장치**다. 절대 빼지 말 것.

#### (e) 멘탈 cap (mentalCap)

```
SPECIAL_TYPES = ['자사고','외고','국제고','과학고','영재학교']

if N < 35:
  for t in SPECIAL_TYPES:
    final_scores[t] = min(final_scores[t], 30)
  mentalCap = 'severe'
elif N < 50:
  for t in SPECIAL_TYPES:
    final_scores[t] = min(final_scores[t], 50)
  mentalCap = 'moderate'
```

UI 영향: cap 발동 시 결과 화면 상단에 빨간/주황 배너 표시 (severe/moderate).

#### (f) 계열 fit cap (careerCapList)

```
if 계열 선택이 unsure가 아니고 비어있지 않으면:
  flags = {eng: 어떤 선택이라도 tracks.eng가 양수, lang: 동일, intl: 동일}

  if not flags.lang:
    final_scores['외고'] = min(final_scores['외고'], 60)
  if not flags.intl AND not flags.lang:
    final_scores['국제고'] = min(final_scores['국제고'], 60)
  if not flags.eng:
    final_scores['과학고'] = min(final_scores['과학고'], 55)
    final_scores['영재학교'] = min(final_scores['영재학교'], 55)
```

UI 영향: cap 발동 시 결과 화면 상단에 청록 배너 표시 (info).

### 5.6 정렬 → 1~3순위

`final_scores`를 내림차순 정렬해 `ranking` 배열 생성.

### 5.7 추천 사유 자동 생성 (buildRationale)

각 순위 항목에 대해 자연어 사유 1줄 생성. **멘탈 cap이 발동하고 해당 학교가 SPECIAL_TYPES에 속하면, 일반 사유 분기를 건너뛰고 보호 메시지 우선 반환**:

- `mentalCap === 'severe'` + 특목고: "정서적 안정성이 평균보다 많이 낮아 회복이 최우선입니다. 강도 높은 학교는 환경 자체가 위험 요인이 될 수 있어 권장하지 않아요."
- `mentalCap === 'moderate'` + 특목고: "정서적 안정성이 평균 이하라 멘탈 보호가 우선입니다. 다른 조건이 좋아도 강도 높은 환경은 적응 부담이 클 수 있어 후순위로 두었어요."
- `mentalCap` + 일반고/자공고2.0: "정서적 안정성 회복이 최우선이라, 안정적인 학교 환경이 가장 중요한 조건이에요." 추가.

학교별 일반 사유 분기는 `index.html`의 `buildRationale` 함수 참조.

## 6. UI/UX 결정사항

### 6.1 검사 진행 화면

- **워크넷 직업심리검사 스타일** 차용: 한 화면에 한 문항만 표시
- **자동 진행**: 리커트 옵션 클릭 280ms 후 다음 문항으로 자동 이동 (B2 multi-select은 예외, 다음 버튼 필요)
- **상단 sticky 진행률 바** + 현재 축 이름 표시
- 이전·다음 버튼 (이전은 첫 문항에서 disabled)

### 6.2 결과 화면 구조 (이 순서)

1. (조건부) 멘탈 cap / 계열 fit cap 알림 배너
2. **추천 1순위** 히어로 카드 (네이비→청록 그라디언트)
3. **6축 종합 프로파일** — 6각형 hexagon SVG 차트 (꼭짓점 좌표는 `index.html`의 `buildHexagonSVG` 참조)
4. **멘탈 유형** — 한자 아이콘(剛/探/精/和/保/衡 등) + 강점/주의 + 5요인 막대 그래프
5. **고교 유형 추천 1~3순위** — 자동 생성 사유 포함
6. **전체 7개 유형 적합도** — 막대 그래프
7. 유의사항 카드
8. 처음부터 다시 / 결과 인쇄·저장 버튼

### 6.3 관리자 콘솔

- 헤더: 응답자 수 + **데이터 소스 배지** (☁️ 클라우드 / 📱 이 기기 / ⚠ 클라우드 연결 실패)
- 클라우드 모드 시 **↻ 새로고침** 버튼
- 통계 카드 4개: 총 응답수, 학년 종류, 최다 추천 1순위, 최다 멘탈 유형
- 검색창 (이름·학년·학교·고교 유형·멘탈 유형)
- 도구: CSV 내보내기, JSON 내보내기, JSON 가져오기(병합), 전체 삭제
- 행 클릭 → 상세 모달 (기본 정보·6축·5요인·고교 추천 순위·39문항 응답 모두)
- 다크 테마 (네이비 배경, 흰 글자)

## 8. 데이터 저장 (Storage Layer)

### 로컬 모드 (Supabase 미설정)

- `localStorage` 키: `'guide_v2_responses'`
- 값: JSON 배열, 최대 2000개 (FIFO)
- 응답 객체 스키마: `{id, name, grade, school, completedAt, answers, careerSelections, axisScore, big5, mentalKey, mentalName, typeScores, ranking}`

### 클라우드 모드 (Supabase 설정 시)

- 테이블: `public.responses` (id PK, name, grade, school, completed_at, payload jsonb, created_at)
- RLS 활성, anon은 INSERT만 가능
- 관리자 RPC 3개: `admin_list(pwd)`, `admin_delete(pwd, rid)`, `admin_clear(pwd)`
- 비밀번호는 RPC 함수 안에 `'YOUR_ADMIN_PASSWORD'` 자리에 인라인 비교
- 클라이언트는 fetch로 `/rest/v1/rpc/admin_list` 호출

> 관리자 인증 흐름: 핀패드 → 입력값을 `cloudList(v)`에 전달 → 성공이면 `currentAdminPassword = v` (세션 변수) 저장 후 사용 / 실패면 `Unauthorized`. **HTML 소스에 비밀번호를 넣지 않는다.**

이 시스템은 5번의 큰 피드백 루프를 거쳤다. 새 구현이 이 결정을 무효화하면 안 된다.

| v2 → 클라우드 | "관리자가 모든 학생 db 다 볼 수 있게 해줘" | Supabase 백엔드 추가, RLS + RPC로 보안, localStorage는 폴백으로 유지 |

## 10. 검증 시나리오 (회귀 방지)

새 구현을 만든 뒤 **반드시 통과**해야 하는 11개 시나리오. `index.html`로 검증된 결과값 그대로:

| # | 입력 | 기대 출력 |
|---|---|---|
| 1 | 인문 단독 + 평균 (A=4 B=4 C=4 D=3 E=3 F_N=3 F_E=3 F_C=4 F_O=3 F_A=4) | 1위 자공고2.0 79 ≈ 자사고 79, 일반고 76, 외고/국제고는 60 cap |
| 2 | 사회 단독 + 평균 | 1위 자공고2.0 79 ≈ 자사고 79, 일반고 76 |
| 3 | 인문+사회 혼합 + 평균 | 동일 패턴 |
| 4 | 심리·교육(mix-psy) + 평균 | 동일 패턴 |
| 5 | 인문 + 학업매우우수 (A=5 C=5 D=4 E=4 F_N=4 F_C=5) | 자공고2.0 100 ≈ 자사고 100, 일반고 94 |
| 6 | 외국어 단독 | 외고 91 (압도적), 국제고 84, 자사고 78 |
| 7 | 국제 단독 | 국제고 91 (압도적), 자사고 81 |
| 8 | 인문 + 멘탈약 (F_N=2) | 자공고2.0 78, 일반고 76, 특목고 모두 30 (severe) |
| 9 | 이공 + 멘탈약 | 자공고2.0 95, 일반고 90, 특목고 모두 30 |
| 10 | 외국어 + 멘탈약 | 자공고2.0 74, 일반고 72, 특목고 모두 30 |
| 11 | 이공 + 학업·멘탈최고 | 과학고 ≥ 영재학교 ≥ 자사고 상위, 외고/국제고는 fit cap 60 |

> 시나리오 1~11에서 단 하나라도 결과가 다르게 나오면 **회귀**. `index.html`로 직접 검증 가능.
